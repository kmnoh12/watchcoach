# 3D 구도 확정 + 목록 썸네일 재촬영 계획 (2026-11-09)

## 결정
- 폰 상세 3D 뷰어의 기본 구도와 목록 썸네일(움짤)을 같은 구도 규칙으로 맞춘다.
- 지금은 움짤을 **만들지 않는다**. 모델 동작이 어색하거나 팔이 뒤틀린 운동이 아직 있어서, 사용자가 PC 뷰어로 검수해 확정한 운동만 나중에 촬영한다.
- 배포는 사용자가 요청할 때만 한다.

## 이미 된 것 (로컬 커밋, 미배포)
- 운동 252개 전체에 구도 배정: `tools/gen_camera_views.py` 규칙 → `tools/viewer3d/camera_views.json` (id → yaw, elev).
  - yaw: 0 정면, 90 옆, 150 뒤쪽. 누운 자세는 옆모습 기준 각도(머리 쪽).
  - 규칙: 앞뒤로 움직이는 운동(로우, 스쿼트, 데드리프트, 푸시다운, 푸시업…) = 옆. 팔꿈치·벌어짐이 중요한 운동(프레스, 레터럴 레이즈, 플라이…) = 비스듬히 정면. 풀업 계열 = 뒤(150, 사용자 선택). 누운 벤치 계열 = 발쪽 비스듬히 위에서.
  - 근거는 병렬 조사 4건 요약이며 대부분 사이트 관례 기반, 짐비주얼 각도를 직접 검증한 건 아님.
- 뷰어(`tools/viewer3d/index.html`, 폰 전용) 변경:
  - 사람이 기구보다 훨씬 크면 사람 중심으로 화면을 잡는다. 바닥 매트는 크기 계산에서 제외.
  - 카메라가 좌우·±20/40° 후보 중 기구에 사람이 가장 덜 가려지는 쪽을 고른다(레이캐스트).
  - `?yaw=&elev=` 로 각도를 바로 시험할 수 있다. `?snap=<진행도>` 모드는 스틸 프레임 촬영용.
- 촬영 도구 `tools/preview_capture.py`: 2개로 시험 완료(24프레임, 192px, 약 20KB). 실제 앱 썸네일 폴더는 건드리지 않음.

## 내일 할 일
1. 사용자가 PC 뷰어로 운동을 검수하고 확정한 운동 id 목록을 준다.
2. 확정 id 목록으로 촬영: `python3 tools/build_app3d_v5.py --extra <rolling_trial>` 후
   `python3 tools/preview_capture.py --ids-file approved.txt --out phone/src/main/assets/previews`, 출력된 주소를 브라우저에서 열어 두면 된다.
3. 확정 안 된 운동은 기존 썸네일을 그대로 둔다(구형 모델이라 나중에 따로).
4. 구도가 마음에 안 드는 운동은 `tools/gen_camera_views.py` 규칙에 예외를 추가하거나 `?yaw=&elev=` 로 찾은 값을 넣는다.

## 아직 남은 구도 문제 (눈으로 본 것)
- 인버티드 로우: 사람이 작게 나옴.
- 푸시업·싯업·플랭크: 매트 위 사람이 여전히 작고 각도가 어색함.
- 풀업 계열은 뒤쪽 구도를 사용자가 직접 골랐음(6번).
- 스쿼트: 옆모습 첫 장면이 서 있는 자세처럼 보임.
- 썸네일 촬영 전에 모델 동작 문제(팔 뒤틀림 등)가 먼저 정리돼야 함.
