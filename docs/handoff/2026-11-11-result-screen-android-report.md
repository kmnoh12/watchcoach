# 운동 결과화면 + 오운완 카메라 공유 구현 보고

작성일: 2026-11-11

## 현재 상태

폰 소스에 결과화면 재구성과 카메라 촬영·사진 선택·비율 변경·기록 합성·저장·공유 연결을 반영했다. 실제 기기에 설치하거나 실행하지 않았다. 따라서 **시안과의 실제 화면 일치, 카메라 동작, 외부 앱 공유 성공은 아직 검증되지 않았다.**

`variants.html` 및 `index.html`의 base64 사진을 제외한 CSS·HTML·JS를 읽고 구현했다. 옛 `camera-share/index.html`은 구현 기준으로 사용하지 않았다.

## 반영한 구성

- 오운완 카드 → 완료 제목 → 숫자 3칸 → 민트 비교 띠 → 종목 카드 → 심박·kcal → 고정 내보내기/확인 버튼 순서.
- 종목 카드는 처음 접힘. 펼치면 세트 번호 / 오늘 / 지난번을 세로로 표시. 세트별 중량과 최고 표시 포함. 일반 세트 행은 편집 기능 없음.
- 추정 세트는 기존 콜백으로 확정. 새 결과화면의 별도 확정 버튼만 해당 입력창을 연다. `MainActivity`의 확정 처리와 `FinishedWorkoutStore.confirmOther`는 변경하지 않았다.
- 카드와 카메라 틀은 같은 22dp 곡률 상수. 카드 버튼은 22−12=10dp. 스크롤 120dp에 걸친 투명도·10dp 이동·0.96배 축소.
- 단일 `PreviewView`를 계속 사용하며 재바인딩 없이 카드에서 카메라로 확장. 펼침 460ms, 곡선 (.2,.8,.2,1). 150ms 뒤부터 300ms 동안 전체 사진의 블러·검정 막을 함께 제거. 컨트롤과 기록은 280ms 뒤부터 등장. 닫을 때 9:16으로 돌아와 역방향으로 접힘.
- 기본 후면 카메라. 허용 전에는 어두운 카드. 버튼을 누를 때 권한 요청. 거절하면 안내만 표시. 권한을 영구 거절한 경우 앱 설정에서 허용해야 한다.
- 원본은 세로 3:4로 보존. 9:16은 좌우, 1:1은 위아래를 잘라 표시. 촬영 후에도 비율 변경 가능. 사진 선택은 시스템 사진 선택기 사용.
- 비율 변경 시 사진 틀 높이·사진 크기·기록 안전 영역·탭 줄을 420ms, 같은 곡선으로 직접 보간. 9:16→3:4가 중간에 1:1을 거치지 않도록 각 크기의 시작/종료 값을 따로 보간한다.
- 사진 틀 폭 기준 cqw 수치를 기록 글씨 배치에 적용. 9:16/3:4는 동일한 3:4 안전 영역을 공유.
- 약 333ms마다 축소 사진에서 왼쪽 위 / 브랜드 / 오른쪽 아래 목록의 배경 밝기를 따로 검사. 밝기 150 기준 검정/흰색, 색 보간 420ms. 별도 깜빡임 방지나 그라데이션 덮개 없음.
- 표시와 저장은 같은 기록 그리기를 사용. 저장 시 실제 원본에서 선택 비율로 자른 후 기록을 합성한다. 저장용 글씨 색도 합성 직전 사진의 각 글씨 영역에서 판정한다.
- 촬영 후 300ms 플래시, 저장/인스타/카카오톡/더보기 버튼, 다시 찍기, 저장 성공 체크 및 ‘갤러리에 저장됨’ 토스트.
- 내보내기 시트는 요약형의 숫자·최고 기록 띠·종목별 최고 세트, 상세형의 모든 세트, 사진 촬영 항목과 텍스트 복사 제공. 이미지에는 시트의 버튼·카메라 미리보기를 포함하지 않는다.

## 시안과 달라진 점과 이유

1. **높이가 짧은 화면:** 원본 시안의 56dp 위 여백과 9:16 사진 높이, 하단 조작부를 모두 유지하면 조작부가 화면 밖으로 나갈 수 있다. 이 경우 카메라 사진 틀을 가용 높이에 맞춰 줄이고, 결과 카드 폭도 같은 값으로 맞췄다. 충분히 큰 화면은 좌우 11dp 기준이다. 짧은 화면에서는 카드가 종목 카드보다 5dp씩 넓다는 비례까지 유지되지는 않는다. 실기기에서 조정 여부를 확인해야 한다.
2. **갤러리 썸네일:** 추가 사진 전체 접근 권한 없이 시스템 사진 선택기를 사용한다. 첫 진입에는 갤러리 아이콘, 촬영/선택 후에는 해당 사진 썸네일을 표시한다. 갤러리의 최신 사진을 자동으로 읽어 표시하지 않는다.
3. **플랫폼 차이:** Android 시스템 글꼴, 기본 사진 선택기/권한창/공유창을 사용한다. 브라우저 글꼴의 줄 높이·자간·안티앨리어싱과 픽셀 단위 일치는 확인하지 못했다. 카드/사진 틀의 22dp 곡률과 사진 위 주요 글자 크기는 코드에 반영했다.
4. **블러 경로:** Android 12 이상에서 실시간 미리보기는 RenderEffect, 그 이전 버전과 정지 사진은 축소 비트맵 블러를 사용한다. 구형 버전의 블러 미리보기 갱신은 약 초당 3회다. 지원 기기별 실제 품질과 성능은 미확인이다.
5. **비교 근거 없음:** 비교할 이전 기록이 없으면 ‘첫 기록’, 조건이나 입력 부족으로 비교할 수 없으면 ‘—’를 표시한다. 시안의 예시 증감이나 최고 기록을 임의로 만들어 표시하지 않는다. 최고 기록이 없으면 내보내기 요약형의 최고 기록 띠도 생략한다.
6. **인스타 스토리 직행:** 프로젝트에서 등록된 Meta App ID를 찾지 못했다. 잘못된 ID를 만들어 넣지 않았다. 현재는 인스타 대상 일반 이미지 공유로 연결하며, manifest의 `com.facebook.sdk.ApplicationId`에 유효한 숫자 ID가 제공되면 `ADD_TO_STORY` 연결을 사용한다. **현 상태의 ‘인스타 스토리’ 버튼이 스토리 편집기로 바로 열리는 기능은 미완료다.** 인스타/카카오톡이 없으면 기본 공유창으로 연결한다.

## 검사 결과와 한계

- 저장소에 `gradlew`가 없다. 설치된 Gradle 8.11.1과 JDK 17로 `:phone:compileDebugKotlin`만 시도했으나, Kotlin 작업 시작 전에 다음 오류로 실행이 중단됐다. native 경로를 임시 폴더로 지정해도 같은 오류였다.

  ```text
  Could not initialize native services.
  Failed to load native library 'libnative-platform.dylib' for Mac OS X aarch64.
  ```

- 대체 검사: 설치되어 있는 Kotlin 2.1.10 컴파일러와 Compose 컴파일러 플러그인, Android 35 및 로컬 캐시 의존성으로 **이번에 바꾼 Kotlin 소스와 테스트 파일만 직접 컴파일**했다. 기존 phone/core의 컴파일된 클래스도 참조하므로 전체 현재 소스의 Gradle 컴파일 성공과 같지 않다.
- `ResultPhotoLayoutTest`만 JUnit 4.13.2로 직접 실행: **3개 통과**. 9:16 좌우 자르기, 1:1 위아래 자르기/3:4 유지, 9:16↔3:4 기록 상하 모서리 고정 검사를 포함한다. 화면 캡처나 카메라 동작 검사가 아니다.
- 변경된 내보내기 시트 Compose 테스트는 직접 컴파일 대상에 포함했다. 실행하지 않았다. UI/스크린샷/전체 테스트/전체 빌드/lint는 실행하지 않았다.
- 기존 `ScreenshotTest`의 옛 결과화면 데이터와 스냅샷은 갱신하지 않았다. 실제 저장 세션과 새 화면으로 시각 검증 후 갱신해야 한다.
- APK 생성·설치·카메라 실행·사진 저장 결과 읽기·외부 공유 앱 진입·성능 측정은 하지 않았다. 시안 일치와 사용자 수용을 완료로 판단할 근거는 아직 없다.

## 못 한 것 / 후속 확인

- 실제 기기에서 카드와 사진이 같은 장면·배율로 이어지는지, 안드로이드 View와 Compose가 겹쳐 그려질 때 모서리·터치·스크롤이 정확한지 확인.
- 실제 촬영의 회전/전면 미러링/잘리는 범위, 밝기별 글씨 색, 전환 애니메이션, Android 10/11 블러 및 메모리 사용 확인.
- 갤러리에 저장된 실제 이미지 비율·기록·색과 UI를 대조.
- 인스타 스토리 직행에 사용할 등록 ID 및 실제 인스타 앱 검증. 카카오톡과 기본 공유창도 실제 앱에서 확인.
- 필요한 후속 컴파일은 `:phone:compileDebugKotlin`, 순수 비율 검사는 `ResultPhotoLayoutTest` 하나로 제한하면 된다. 전체 테스트나 전체 빌드를 이번 작업의 필수 후속 단계로 요구하지 않는다.

## 보존한 범위

`design/`, `docs/design/`의 시안 원본, `WorkoutData.kt` 및 `WorkoutDataTest.kt`의 기존 미커밋 변경, `wear/`, 측정 엔진은 수정하지 않았다. `MainActivity.kt`, `FinishedWorkoutStore.kt`, Gradle 의존성과 버전도 변경하지 않았다. 커밋·배포·버전 증가는 하지 않았다.
