# 운동 기록 탭 반영 결과 — 2026-11-13

## 반영
- HTML은 사용자 후속 지시대로 브라우저 없이 CSS/JS 소스로 읽었다. 기록 화면에만 중립 회색 KColors와 화면 전용 day/wash/accent2, 고정폭 숫자를 적용했다.
- 큰 제목과 + 없는 상단, 14dp 달력/기록 카드, 8dp 기록 날짜 표시, 실제 오늘의 얇은 테두리, 연도/월 글자 위계, 월별 기록 수, 48dp 날짜 블록과 운동 정보/볼륨/메뉴를 반영했다.
- 76dp 동일 높이의 선택 상단: 원형 전체 선택, 숫자만 청록인 선택 수, 취소, 비활성 상태를 포함한 빨간 삭제 버튼. 카드 선택은 Selected 면과 안쪽 1.5dp 테두리이며 선택 중 메뉴는 숨긴다. 중간 상태 표시와 이전 네모 체크박스는 제거했다.
- 전체 선택/해제는 보이는 달에만 적용한다. 달이 바뀌면 숨은 선택을 비우고, 삭제는 선택한 목록과 `false`를 기존 `deleteRecords`에 전달한다. 기존 MainActivity 확인 팝업/실제 삭제 코드는 변경하지 않았다.
- 길게 누르기 햅틱, 뒤로가기로 선택 해제, 좌우 스와이프/화살표 월 이동을 유지했다. 확정 하단 탭바 코드는 수정하지 않았다.
- 기존 +는 클릭 동작이 연결되지 않은 표시였다. 제거로 새로 접근 불가능해진 직접 추가 기능은 확인되지 않았고 기능 코드는 삭제하지 않았다. 시안에 없는 최근 완료 결과 배너는 기록 탭에서 표시하지 않으며 `lastResultTitle`, `openResult` 및 결과 화면 코드는 유지했다. 개별 카드로 결과 화면을 여는 동작도 유지했다.

## 검증
설치된 JDK17/Gradle 8.11.1로 다음 범위만 실행했다.

```sh
gradle :phone:compileDebugKotlin :phone:compileDebugUnitTestKotlin \
  :phone:testDebugCompose -Proborazzi.test.record=true \
  --tests '*RecordsAndResultMenuTest'
```

- 컴파일 2개 통과, RecordsAndResultMenuTest 9개 통과(실패/스킵 0).
- 개별 기록 열기, 부분 선택, 전체 선택→삭제 콜백, 전체 해제/0개 삭제 비활성, 다른 달 제외, 월 이동 시 선택 초기화, 양방향 스와이프, 취소/뒤로가기, 메뉴 복구, 기존 결과 내보내기를 확인했다.
- 360dp/412dp 각각 평소/선택 상태를 Roborazzi로 렌더해 HTML 소스의 배치와 육안 대조했다. 시안의 세 기록/문구는 잘림·겹침이 없고 탭바도 남는다. 선택 전후 달력 상단 위치와 카드 전체 경계가 동일한지도 테스트로 확인했다.
- PNG: `phone/build/outputs/roborazzi/records_{normal,selecting}_{360,412}.png`. 같은 화면을 연속 캡처하면 두 번째 이미지에서 변경되지 않은 부분이 누락되어, 상태별 독립 테스트에서 한 번씩 캡처하도록 수정한 뒤 최종 이미지 4장을 확인했다.
- 최종 로그: `work/records-tab/checks.log`. `git diff --check` 통과. 시작 시점의 다른 미커밋 파일들과 TabScreens의 기록 화면 밖 부분이 그대로인지 해시 비교로 확인했다(필요한 import 두 줄 제외).

## 범위와 한계
- 변경: `phone/.../ui/TabScreens.kt`의 기록 화면 부분, `phone/.../ui/RecordsAndResultMenuTest.kt`, 이 보고서만.
- 실제 기기 설치/동작, 실제 햅틱, 실제 저장 기록 삭제는 실행하지 않았다. 삭제 테스트는 기존 확인 흐름으로 넘기는 목록/플래그까지 검증했고, 확인 팝업/영구 삭제 구현은 소스로 연결 유지 여부를 확인했다.
- 브라우저 시안 렌더 대조는 후속 지시로 생략하고 HTML 소스와 앱 PNG를 대조했다. 커밋·푸시·배포는 하지 않았다.
