# 가상 워치 기반 운동 측정 개선 — 실행 계약

2026-11-16. 사용자 최신 지시가 기존 3종 파일럿의 ‘엔진 수정 없음’ 범위를 대체한다.
목표는 재현 도구 완성이 아니라 **보고된 부정확한 운동의 원인 수정, 이후 전체 카탈로그에서 자동측정 가능한 조건의 검증**이다.
합성 성공과 실제 Watch8 정확도 성공은 별도 상태다. 배포는 이 작업에 포함되지 않는다.

## 1. 고정 분모와 근거

- 현재 폰 카탈로그는 중복 없는 **250종**. 실제 Kotlin 프로필 해석 결과 자동측정 경로 206종, 기존 수동 정책 40종, 시간 측정 4종이다.
- 206은 ‘현재 자동 경로에 배정된 수’이지 ‘실제 자동측정 가능성이 증명된 수’가 아니다. 기존 수동 40종도 근거를 검토한다. 단순히 현재 수동이라는 이유만으로 잠재 후보를 제외하지 않는다.
- 손목과 움직이는 부위가 분리된 조건은 손목만으로 관측 불가일 수 있다. 운동명뿐 아니라 변형·프로토콜·착용 손·그립·개인 보정 상태를 결과 키로 삼는다.
- 각 결과는 UNTESTED / FAIL / FIX_CANDIDATE / SYNTHETIC_PASS / REAL_REPLAY_PASS / WATCH8_VERIFIED / SOURCE_BLOCKED / OBSERVABILITY_LIMIT / HOLD로 보존한다. FAIL을 목록에서 지우거나 분모에서 빼지 않는다.
- 정본 증상: 옵시디언의 projects/개인용 스마트폰·갤럭시워치 운동기록 앱 개발 계획.md §1,3–7,11,13–14,34 및 NEXT_PLAN.md D/E/F. 과거 기록보다 최신 사용자 정정을 우선한다.
- **2026-11-16 사용자 정정:** 정상 대조는 바벨 벤치(flat_bench)와 덤벨 숄더 프레스(dumbbell_shoulder_press)다. 시티드 로우는 미해결 문제군이며, seated_row/cable_seated_row는 정확한 변형·실패 양상을 단정하지 않고 공통 경로부터 조사한다. 과거 한 세트 성공이나 종류 미확정 숄더 프레스 오류를 현재 상태로 일반화하지 않는다. 기존 덤벨 컬·레터럴·바벨 오버헤드는 합성 파일럿 대조일 뿐 실물 정상 확인과 구분한다. 이 정정은 새 Watch8 정답 라벨 검증이 아니다.
- 기계 판독 입력: tools/virtual_watch_campaign_issues.json. 현재 해석·모델 대응표: work/virtual-watch/campaign/inventory.json. 재생성: VirtualWatchCampaignInventoryTest 하나 실행 후 tools/virtual_watch_campaign_inventory.py.

### 이미 발견한 검증 구멍

1. 기존 재생기는 3종과 일반 검출기만 검사한다. 준비 자세, 목표 뒤 추가 카운트 거르기, 종료 판정, 진동 예약, 저장된 학습 패턴은 검사하지 않았다.
2. 운동 ID와 표시 모델 ID는 다르다. 예: machine_fly는 pec_deck~m=fly, 머신 벤치는 chest_press_variants~m=flat_bench다. 실제 앱의 exercise_models.json을 통과하지 않은 이름 매칭은 금지한다.
3. 연결된 모델 247개 중 묶음 기록과 현재 PC 원본·실제 압축 파일의 해시가 함께 맞는 것은 244개다. 두 레터럴 레이즈는 PC 원본과 앱 묶음 기록이 다르고, 롤링 익스텐션은 현재 PC 원본 근거가 부족하다. 원본에 맞춰 폰 자산을 덮어쓰지 않는다.
4. 기본 catalog_trial에서 최종 손목 변환 자료가 없는 모델은 wide_pulldown_machine과 rolling_triceps_extension이다. 승인된 추가 소스 또는 실제 앱 표면에서 독립적으로 복원 가능한지 확인하고, 없으면 SOURCE_BLOCKED다.
5. ‘묶음 생성 기록과 해시 일치’는 직접 압축 해제·좌표 비교나 동작의 육안 승인을 대신하지 않는다. 최초 실행에서 이 둘을 따로 기록한다.

## 2. 원인을 나눠서 증명하기

수정 전에 아래 층 중 무엇이 실패했는지 남긴다. 모델의 움직임 오류를 엔진 임계값으로 덮지 않는다.

| 층 | 확인 사항 | 원인 증거 |
|---|---|---|
| 동작 원본 | 실제 폰 표시 모델/PC 모델/사용자 동작의 방향·왕복·그립 | 모델 대응표, 압축 해제 비교, 연속 재생, 사용자 보고와 다른 점 |
| 가상 장착 | 손등 위치, 우수 좌표계, 회전·이동, 손목/손바닥 혼동 | 최종 스킨과 별도 표면 피팅의 위치·회전 잔차; 좌/우 독립 검사 |
| 관측 신호 | 회전, 수직/수평 이동, 중력 방향 변화 중 무엇이 반복을 담는가 | accel-only / gyro-only / fusion 절제 비교, 축·자세 변화 대조 |
| 검출 | 준비/첫 반복, 축 잠금, 필터, 왕복 짝짓기, ROM·시간 조건 | 실패 전후 최소 입력과 거절 이유, 정상 대조 운동 |
| 세트 생명주기 | 목표 뒤 정지·계속하기·기구 내려놓기, 이벤트 지연 | 실제 core 게이트/가드 호출 순서의 재생, count/cue/end 개별 기록 |
| 실물 전달 | 센서 품질, 비동기 콜백, 진동·폰 음성 지연 | Watch8 원시 기록+수동/영상 정답; 합성 결과로 대체 불가 |

한 수정은 원인 가설 하나만 바꾼다. 가설 → 기존 실패 입력 → 최소 수정 → 수정 후/독립 입력 → 정상 대조 → 남은 한계를 기록한다.

## 3. 동작별 센서 선택 기준

아래는 검사할 계약이지, 새 임계값을 일괄 적용하라는 지시가 아니다.

| 동작 특성 | 우선 비교할 신호 | 피해야 할 가정 / 진단 |
|---|---|---|
| 컬·푸시다운처럼 전완 기울기가 변함 | 중력 방향 변화와 자이로의 부호 있는 왕복 | 중력 기울기를 팔꿈치 각도로 부르지 않는다. 현재 FLEXION_EXTENSION은 선언상 ROTATION_ENERGY지만 실제로 시작 중력 자세의 60° 이탈/20° 복귀를 사용한다. 팔 벌림·시작 자세에 민감한지 확인한다. |
| 손목 회전이 작은 이동성 프레스 | 중력을 분리한 3축 가속도, 회전 보정, 왕복 방향 | 중력 축 투영 하나로 수평·대각선 이동을 놓치는지 검사한다. 스칼라 크기 피크 하나를 1회로 취급하지 않는다. 정상 바벨 벤치 경로를 보존한다. |
| 숄더 프레스·머신 상하 이동 | 수직 성분 및 복귀 신호, 자이로는 자세/흔들림 구분 | 상단 반전과 완전 복귀를 분리한다. 정지 뒤 필터 잔류가 추가 반복이 되는지 검사하되, 사용자가 정상 확인한 덤벨 숄더 프레스는 보호한다. 종류 미확정 과거 오류를 덤벨 또는 다른 변형에 임의 배정하지 않는다. |
| 플라이·리버스 플라이·풀오버 | 손목 회전축의 부호 있는 궤적 + 이동 성분 | 한 평면의 정상 원호가 MULTI_AXIS의 보조축 에너지 조건 때문에 거절되는지 확인한다. 어깨 통증을 감수하는 ROM/과도하게 느린 템포를 요구하지 않는다. |
| 랫풀다운·스트레이트암·로우 | 실제 손목 이동/회전의 양방향 주기 | 첫 2회 뒤 축 잠금/후보 상태, 당긴 꼭짓점의 조기 확정, 손잡이 내려놓기 오류를 분리한다. 시티드 로우는 미해결로 조사하되, 다른 당기기 운동의 증상을 시티드 로우의 확인된 증상으로 간주하지 않는다. |
| 외회전 | 적응 회전축에 투영한 자이로, 충분한 왕복 변위 | 기기 고정 X/Y/Z축에만 의존하지 않는다. 손목 돌림과 상완 자세는 동일 정보가 아니다. |
| 손목이 거의 안 움직이는 하체 기구·정적 유지 | 관측 한계 / 시간 측정 | 운동 모델의 무릎 움직임을 손목 센서에 주입해 가짜 성공을 만들지 않는다. 기존 수동 분류 중 관측 가능한 예외는 별도 검토한다. |

가속도(m/s², 중력 포함), 자이로(rad/s), 장치 좌표, 센서 측정 시각과 수신 시각은 각각 보존한다. 공식 정의: Android Motion sensors 및 SensorEvent. 소프트웨어 선형 가속도/자세 센서가 모든 장치에 있다고 가정하지 않는다.

## 4. 성공 조건 — 정답을 엔진에 주입하지 않기

- 독립 정답은 실제 표시 동작/수동 영상에서 만든다. 검출 이벤트·목표 횟수·검출 신호 피크로 정답을 다시 만들지 않는다. 합성 일정은 재생기가 실제로 왕복하는 동작인지 먼저 확인한다.
- 정상 왕복마다 실시간 이벤트가 1개씩 대응해야 한다. 합계만 맞거나 offline flush로 마지막 반복을 채우면 실패다. 시작 준비·정지·기구 내려놓기에는 추가 반복이 없어야 한다.
- 목표 10회라도 계속한 정상 11·12회는 기록되어야 한다. 목표 수로 잘라서 과검출을 숨기지 않는다. 첫/둘째 세트와 정방향/역방향 시작을 검사한다.
- **‘완전 복귀보다 약간 먼저 검출’은 그 자체로 오류가 아니다.** 검출 이벤트 시각, 실제 방출 시각, 진동 예약 시각, 실물 진동 시각을 나눈다. 반대편 꼭짓점/운동 초기에 울리는 오류와 복귀 막바지 피드백을 구별한다.
- 타이밍은 복귀 구간의 위치와 ms 오차를 함께 기록한다. 현재 파일럿의 −100~−400ms는 기준 자료이지 모든 운동의 합격 창이 아니다. 실제 허용창을 확인하지 못하면 timing_pending이며, 임의 ms 기준으로 모두 합격 처리하지 않는다.
- 종료 정책은 목표 정확히 도달 후 정지 1.0초, 목표 전 7초, 초과 후 기본 3초 및 현재 진행 중 후보의 유한 유예를 보존한다. 목표 알림 2펄스와 실제 종료 3펄스를 섞지 않는다.
- 실제 서비스가 쓰는 현재 core 검출기·StartPoseGate/종료 게이트·목표 뒤 가드·RepCueDelay를 재사용한다. Android 서비스 전체 재현이 아닌 테스트는 coverage_gap에 빠진 경로를 명시한다. 학습 패턴을 일반 검출기 성공으로 대신 인증하지 않는다.
- 실행 시간·메모리·50Hz 처리 여유는 별도 기록한다. 벤치마크 수치만으로 실제 워치 전력/지연을 인증하지 않는다.

## 5. 입력 변화와 노이즈 검증

우선 정상 속도를 중심으로 검사한다. 아래 수치는 **실측 장치 분포가 아닌 결정적 스트레스 가정**이며 소스/시드와 함께 저장한다.

1. 원본 템포, 0.8/1.25배 주기, 느린 복귀·짧은 끝 멈춤. 매우 느린 경우만 성공하는 것을 정상 성공으로 인정하지 않는다.
2. 손등 착용 기준; 안전한 회전행렬로 장착 방향 ±15°, 위치 ±10mm, 시작 자세/동작면 변화. 오른손은 실제 오른쪽 표면에서 따로 추출한다.
3. 가능한 운동에 한해 편한 ROM 변형. 원본 프레임을 재생 범위로 제한하거나 실제 변형 모델을 사용하며, 센서 출력에 비율만 곱해 관절 ROM이라고 부르지 않는다. 그립·접촉·동작 유효성 확인 후 사용한다.
4. 무잡음 → 축별 accel 표준편차 0.03/0.10 m/s², gyro 0.005/0.02 rad/s; 바이어스·저주파 드리프트는 별도 축/단계. 고정 시드 11/29/47, 수정에 쓰지 않은 101/307을 보류 평가에 사용한다.
5. 이벤트 시각과 수신 시각을 분리한 0/40/120ms 지연, accel/gyro 위상차, 누락 1/3개 및 450ms 초과 단절. 단절 구간은 무조건 추정 카운트하지 않고 신뢰도/미측정을 남긴다.
6. 별도 null: 장착·그립 조절, 시작 전 흔들림, 목표 뒤 완전 정지, 기구 내려놓기, 손목만 까딱하기. 내려놓기 동작을 기존 정적 꼬리로 대체하지 않는다.

필터 변경은 타임스텝 의존성, 위상 지연, 느린 유효 동작 제거 여부까지 비교한다. ‘노이즈 감소’는 잔차/오검출·누락 변화로 표현하고, 노이즈 가정을 통과했다고 실물 잡음을 해결했다고 말하지 않는다.

## 6. 순서와 변경 경계

1. 최우선: 목표 뒤 +1(풀오버·머신 벤치; 과거 숄더 기록은 종류 미확정), 머신 프레스 방향성, 플라이 보통 속도/편한 ROM. 이어 시티드 로우·스트레이트암·랫풀다운·리버스 플라이·푸시다운·로프 해머 컬. 덤벨 숄더 프레스는 현재 실패 목록에서 제외한다.
2. 원본/장착/일반 검출/세트 생명주기를 연결하고 첫 작은 묶음에서 실제 최소 수정까지 끝낸다. 새 거대 프레임워크 설계만 하고 끝내지 않는다.
3. 같은 원인/가족의 운동 묶음으로 확장하되 ID별·조건별 결과는 남긴다. 사용자가 정상 확인한 바벨 벤치/덤벨 숄더 프레스를 보호한다. 이전 3종 파일럿 사례는 합성 회귀 대조로 별도 유지한다.
4. 나머지 자동 206종 및 수동 40종의 관측 근거를 빠짐없이 처리한다. 한 팔·교대·다중 모델 매핑은 한 모델의 통과로 전부 인증하지 않는다.
5. 실패/근거 부족이 남으면 ‘모두 성공’은 미완료다. 실물 데이터가 없으면 합성 개선까지 보고하고 Watch8 단계는 미확인으로 남긴다.

수정 허용: 관련 core/wear 측정 코드, 좁은 회귀 테스트, 기존 가상센서 도구와 이 계획. UI·기존 썸네일·사용자 미커밋 작업·릴리스·API 설정은 건드리지 않는다. 디자인 오류는 증명한 해당 동작만 별도 교정 대상으로 기록하고, 기존 Blender 검토 규칙과 연속 재생 확인을 거쳐야 한다. 임계값 일괄 하향/운동 수동 전환으로 성공률을 꾸미지 않는다.

## 7. DeepSeek 실행 / 세션 중단선

요청된 모델은 DeepSeek V4.1 Flash, 로컬 프록시를 통한 DSH다. 직접 API키 접근·다른 모델 대체·새 에이전트 재위임은 금지한다.

- 배정 원본은 docs/VIRTUAL_WATCH_ENGINE_BATCH_01.md다. 실제 실행은 work/virtual-watch/campaign/dsh-sessions/ 아래에 **운동 1종당 새 task.md와 새 DSH 세션**으로 만든다. 한 세션이 끝나고 결과를 독립 검토한 뒤에만 다음 운동을 새 세션으로 시작한다. 완료한 운동의 긴 대화 문맥을 다음 운동에 넘기거나 여러 운동을 같은 세션에 추가하지 않는다.
- **2026-11-16 사용자 승인:** 전체 달러 비용 상한을 요구하던 대기는 해제하고, 비용 상한 없이 순차 진행한다. 이는 dsh-flash-astra 스킬의 숫자 예산 선행 규칙보다 최신인 이 작업의 명시적 지시다. 다만 여러 작업을 한 세션에 몰아 비용이 커지는 것을 막기 위해 운동 1종, 최대 25분, 같은 오류 3회 또는 15분 무진전 중단선은 유지한다.
- 현재 상태: 첫 새 세션은 machine_fly 하나만 맡긴다. 요청당 출력 상한과 실제 모델 요청 수를 런타임이 강제하지 못하면 이를 강제됐다고 쓰지 않는다. 비용 무제한 재시도나 동시 세션은 금지하고, 항상 한 세션만 보이는 터미널에서 실행한다.
- 3번 연속 같은 오류 또는 15분 무진전이면 상태/근거를 남기고 그 세션을 종료한다. 잔액 부족은 속도 제한으로 취급하지 않으며 반복 재시도하지 않는다.
- 실행 세션의 danger-full-access / approval never를 실제로 확인한다. 보이는 터미널 세션과 추적되는 작업/대기자를 사용한다. 모델 생존 여부가 아니라 수정 파일·완료 항목·검증 결과를 감시한다.
- 정상 실행 중인 작업자를 지시 추가 때문에 죽이지 않는다. 같은 미완료 묶음의 후속은 실제 DSH --session-id로 이어 간다. 현재 Mac ds-run의 resume 플래그 전달 한계는 직접 검증된 CLI 경로로 보완하며, 공유 스크립트를 몰래 수정하지 않는다.

## 8. 현재 완료 / 미완료

- 완료: 정본 증상 및 비교 운동 목록, 250종 실제 프로필/모델 대응표, 묶음 출처 검사, 이 성공 계약, 첫 실행 지시서.
