# 가상 워치 센서와 카운팅 엔진 오프라인 검증

2026-11-16 기준. 실제로 실행한 3종목 파일럿과 재현 방법을 기록한다.

## 범위 갱신 (2026-11-16)

이 문서는 완료된 3종 파일럿의 설계/제약을 보존한다. 최신 사용자 요청으로 이제 실제 원인 수정과 전체 카탈로그 개선을 진행한다. 실행 범위와 성공 조건은 [엔진 개선 계약](VIRTUAL_WATCH_ENGINE_CAMPAIGN.md)을 따른다. 아래의 ‘엔진 수정 없음’은 파일럿 당시 범위이지 새 작업의 금지가 아니다.

### 입력층 후속 — 뷰어 선형 경로와 C2 변주 분리

- 게시 뷰어는 저장 프레임 사이 정점을 선형 보간한다. 이 경로를 그대로 두 번 미분하면 프레임 매듭의 속도 불연속이 가짜 가속도 스파이크가 된다. 덤벨 풀오버의 왕복 일정에는 내부 매듭 통과가 46회 있고, 매듭에서 미분 간격 1 ms와 0.5 ms의 가속도 차이는 35.924~127.390 m/s²였다.
- 기존 자연 C2 위치/연속 쿼터니언 성분 스플라인은 **같은 게시 프레임 매듭을 통과하는 별도 진단 변주**다. 뷰어의 정확한 선형 표면이나 실물 손목 궤적과 같은 정답으로 취급하지 않는다. 생성 manifest에는 두 lane의 ID·보간 방식·`physical_ground_truth=false`를 따로 저장하고, 구분이 없으면 검증 단계에서 거부한다.
- `lying_dumbbell_pullover`는 기존 3종 `PILOT` 기본 실행에 섞지 않고 `C2_VARIATIONS`에만 추가했다. 생성 케이스는 미분 안정성 0.000101 m/s², 게시 손 표면 최대 차이 0.448 mm, 정지·접합 검사를 통과했다. 다만 손 방향 변화가 0°라 합성 자이로도 사실상 0이다. 이는 입력 생성 가능성만 뜻하며 검출기 성공이나 실제 Watch8 정확도를 뜻하지 않는다.

## 범위와 현재 상태

완성된 V5 동작에서 왼손목의 위치·방향을 복원하고, 그 위에 가상 워치를 고정해 합성 가속도·자이로를 만든다. 이 신호를 **현재 프로덕션 카운터와 수직 진폭 필터를 바꾸지 않고** 오프라인으로 재생한다. 원래 애니메이션을 재구성하거나 감지 임계값을 조정하지 않는다.

손바닥 쪽으로 뒤집혔던 첫 장착을 사용자가 지적해, 실제 센서 중심과 좌표계를 손등 쪽으로 수정했다. 아래 결과는 수정 후 케이스다. 수치상 부착 일치·재생·카운팅은 확인했지만, 화면의 최종 육안 승인과 Watch8 실측 검증은 완료로 취급하지 않는다.

## 1. 입력과 손목 복원

- 입력은 게시된 V5의 base.json, 운동별 JSON, manifest.json과 설계 폴더의 **최종 catalog_trial/<id>.skin.bin**, anatomical_rest.json이다. 초기 <id>.input.npz의 팔레트를 사용하지 않는다.
- 게시 경로는 Library/Application Support 아래 __PROTECTED_WATCHCOACH_VIEWER__/v5-catalog를 우선 찾고, 없으면 WatchGymViewer/v5-catalog를 찾는다. 이 Mac에서는 후자를 사용했다. --viewer-root로 명시할 수도 있다.
- 3종목 모두 65개 저장 자세, 52개 뼈, 893개 정점이다. 최종 skin 파일은 little-endian float32, (65, 52, 4, 4), 행 우선 배열이다.
- 손 뼈 팔레트는 역바인드가 곱해진 변환이므로 다음과 같이 복원한다. 팔레트의 이동 성분만 손목 좌표로 사용하면 안 된다.

~~~text
T_world_hand  = final_skin_hand × bind_hand
T_world_watch = T_world_hand × T_hand_watch
~~~

- hand_l의 순수 가중치 정점 464, 469, 470, 476을 게시 표면과 모든 저장 자세에서 비교한다. 별도의 강체 맞춤으로 원점과 회전을 다시 대조한다. 이번 3종목의 표면 최대 차이는 0.00014 mm 미만이었다.
- 반사·비강체 변환을 거부하고, 통과한 float32 반올림만 정규 직교화한다. 입력 파일은 읽기만 하며 생성 전후 내용 지문도 비교한다.

## 2. 손등 장착과 좌표계 수정

이 파일럿의 착용 가정은 **왼손, 화면 위쪽이 팔꿈치 방향**이다.

- +Y: 화면 위 / 팔꿈치 쪽.
- +X: 화면 오른쪽 / 새끼손가락 쪽. 이 왼손 배치에서는 엄지 쪽이 아니다.
- +Z: 화면 바깥 / 손등 바깥. 케이스 뒷면은 -Z, 피부 쪽이다.
- 손목 관절에서 센서 중심까지 기기 축 기준 오프셋은 (0, 0.012, 0.028) m다. 이는 실측 센서 위치가 아니라 진단용 가정이다. 케이스와 스트랩의 피부 밀착·충돌·연부조직은 시뮬레이션하지 않는다.

첫 구현은 +X를 엄지 쪽으로 잡아 cross(X,Y)가 손바닥을 향했다. 수정은 Y를 유지한 채 X와 Z를 함께 반전하는 180도 회전이다. **Z만 반전한 반사 행렬이 아니며**, 센서 중심도 반대쪽으로 약 56 mm 이동한다. 표시만 돌린 것이 아니라 합성 신호와 미리보기가 같은 수정 변환을 사용한다.

독립적인 정규 왼손 예제(손가락 아래, 엄지 화면 왼쪽, 손등 +Z)로 손등 위치·올바른 회전·화면 앞뒷면을 검사한다. 원래 계산이 이 검사에서 실패하고 수정 후 통과함을 확인했다.

가속도계·자이로는 케이스에 고정된 가상 관성 센서다. 광학 심박 센서를 재현하는 작업은 아니며 심박 필드는 비어 있다.

## 3. 합성 신호와 독립 기준 반복

- acts는 시간 대신 진행률이다. 뷰어와 같은 왕복 이징, playback_ms, playback_range를 쓴다. 기본 주기 2.6초이며 프레스는 원본 진행 0~0.93을 왕복한다. 명시적 cycle 입력은 별도 전환 라벨 없이는 이 파일럿에서 거부한다.
- 위치는 자연 C2 스플라인, 회전은 부호를 연속화한 쿼터니언 성분 스플라인을 정규화해 보간한다. 게시 표면의 선형 보간과도 비교한다. 수정 후 최대 손 표면 차이는 컬 0.040 mm, 레터럴 0.042 mm, 프레스 0.783 mm 미만이다.
- 가속도는 Rᵀ(p″−g), g=(0,0,−9.80665) m/s²다. 자이로는 상대 회전의 회전벡터를 중앙 시각 기기 좌표계로 옮겨 시간으로 나눈 값(rad/s)이다.
- 미분 간격 1 ms를 0.5 ms로 줄여 안정성을 확인한다. 샘플링은 50 Hz이고 준비 정지 3초, 종료 정지 8초를 붙인다. 정지 중 중력 크기·자이로 0과 왕복 접합 속도를 검사한다.
- 기준 반복의 시작·전환·완료 시각은 카운터 출력과 독립적인 재생 시간표에서 만든다. 종료는 정지이며 기구를 내려놓는 동작은 포함하지 않는다.

## 4. 저장과 재생

생성물은 Git 제외 경로 work/virtual-watch/<case-id>/에 저장한다.

| 파일 | 내용 |
|---|---|
| capture.kcs | 기존 KCS v2의 big-endian 6축 기록, 50 Hz |
| truth.json | 독립 기준 반복, 준비·종료 구간 |
| manifest.json | synthetic 출처, 설정, 입력·생성기·미리보기 내용 지문, 수치 검사와 한계 |
| preview.json / preview.html | 같은 센서 자세와 수정하지 않은 게시 표면의 비교 미리보기 |
| replays/<engine-revision>/result.json | 감지 이벤트, 적용 프로필, 기준 반복별 대응과 시간차 |
| replays/<engine-revision>/events.tsv | 원시 감지 이벤트 |

하드웨어 정확도·심박·실제 콜백 도착 시각은 unknown(-1)으로 기록한다. 가상 가속도·자이로 타임스탬프는 동일한 단조 증가 시계다. 시작값은 1,000,000,000 ns다.

케이스 ID에는 입력 자료뿐 아니라 생성기와 미리보기 내용, 장착 설정이 들어간다. 동일 입력 재생성 시 기존 캡처와 기준 파일이 바이트 단위로 같은지 확인하며 기존 결과를 덮어쓰지 않는다. 이번 수정 후 3종목 모두 재현을 확인했다.

재생기는 임시 TSV로 필요한 입력만 Kotlin에 전달하고 다음 **단일 테스트 클래스**만 실행한다.

~~~sh
:core:test --tests dev.kyungmin.watchcoach.core.VirtualWatchReplayTest
~~~

- 기존 SensorCaptureFormat, SensorCaptureReplay, ExerciseTrackingProfiles, ProfiledMotionRepDetector를 사용한다. 수직 계열은 프로덕션 VerticalRepAmplitude 필터도 적용한다.
- 준비 구간은 서비스와 마찬가지로 반복 감지기에 넣지 않는다. 준비 종료 경계까지 제외하고 첫 작업 샘플 직전에 beginCounting을 호출한다. 첫 투입 시각은 4.020초(가상 절대시계)다.
- finishAll에서만 나오는 이벤트는 offline_flush로 별도 기록하며 live 횟수에 섞지 않는다.
- 기준 사이클에 속한 감지 전환점으로 1:1 대응한다. 총합이 같아도 한 반복의 중복과 다른 반복의 누락을 성공으로 숨기지 않는다. 횟수 불일치는 도구 실패가 아니라 baseline 결과로 보존한다.
- 엔진 지문은 Git HEAD만이 아니라 실제 core 소스, 서비스, 선택 테스트, Gradle 설정과 실행기 내용을 사용한다. 실행 전후 이 자료가 같아야 결과를 게시한다.

## 5. 수정 후 결과

|---|---:|---:|---:|
| 덤벨 컬 | 10 / 10 | 0 / 0 | 300 ms |
| 덤벨 레터럴 레이즈 | 10 / 10 | 0 / 0 | 100~180 ms |
| 바벨 오버헤드 프레스 | 8 / 8 | 0 / 0 | 400 ms |

3종목 모두 수직 진폭 거절과 offline_flush 전용 이벤트가 없었다. 레터럴은 이벤트 내부 종료 시각이 완전 복귀보다 500 ms 빠르고, 그 이벤트를 실제 반환한 시각은 320~400 ms 뒤였다. 이벤트 시각과 출력 시각은 따로 기록한다.

**정확한 횟수와 적절한 감지 시점은 다른 판정이다.** 여기서 조기 출력은 독립적인 완전 복귀 시각과의 차이이며, 실전에서 허용할 타이밍 기준이나 앱 오류 판정으로 단정하지 않는다. 카운터를 이 이상적 합성 신호에 맞춰 조정하지 않았다.

## 6. 실행과 확인 범위

저장소 루트에서 실행한다. Python은 NumPy가 필요하다. 실행기의 기본 Gradle/JDK는 이 Mac의 인접 안드로이드-에뮬레이터 폴더이며 --gradle, --java-home으로 지정할 수 있다.

~~~sh
python3 tools/gen_virtual_watch_pilot.py
python3 tools/replay_virtual_watch_pilot.py
python3 tools/gen_virtual_watch_pilot.py --verify
~~~

코드의 좁은 검사: 기존 Python 17개와 이번 손등 회귀 1개를 확인했다. Kotlin은 지정 클래스의 3개 검사만 실행했고 모두 통과했다. 전체 테스트·앱 빌드·배포는 하지 않았다. 캡처·기준·manifest·엔진 결과의 출처 지문과 입력 불변성을 대조했다.

미리보기는 3종목의 재생·진행 조절·손등/옆면 선택을 실행하고 화면을 저장했다. 수정 케이스에서 새 JavaScript 오류는 없었다. **이 실행 환경은 화면 이미지를 판독하지 못하므로 스크린샷 저장이나 수치 대조를 육안 승인으로 보고하지 않는다.**

검증하지 않은 것:

- 실제 Watch8의 축 등록·스트랩 정렬·피부 밀착·노이즈·누락·센서 지연.
- 사용자 학습 패턴, 자동 시작/세트 종료/목표 후 보호, 서비스 전체 수명주기.
- 현재 PC 게시 동작과 폰 앱 자산이 같은 버전인지 여부.
- 실제 운동의 속도 변화, 불완전 반복, 기구를 내려놓는 동작.

앱 데이터·애니메이션·임계값·배포물은 변경하지 않았다. 별도 사용자 승인 없이 배포하거나 실측 검증으로 확대하지 않는다.
