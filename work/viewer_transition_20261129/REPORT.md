# 워치코치 운동 간 전환 프로토타입

[38.5초 영상](./transitions.mp4) · [7개 장면 프레임 스트립](./strip.jpg)

운동 전환을 요청하면 진행 중인 반복을 원래 속도로 끝까지 재생한다. 그동안 현재 카메라를 유지하고 다음 운동을 미리 불러온다. 반복 경계부터 2초 동안 한 캐릭터가 다음 시작 자세로 움직이며 기구와 카메라가 바뀐다. 도착하면 다음 운동의 기본 구도로 원래 반복을 시작한다.

| 영상 시각 | 장면 |
| --- | --- |
| 00:00.0 | 덤벨 컬 → 플랫 벤치프레스 |
| 00:05.2 | 플랫 벤치프레스 → 랫 풀다운 |
| 00:10.4 | 랫 풀다운 → 스탠딩 케이블 컬 |
| 00:15.6 | 덤벨 컬 → 컨벤셔널 데드리프트 |
| 00:20.8 | 컨벤셔널 데드리프트 → 플랫 벤치프레스 |
| 00:26.0 | 덤벨 컬 반복 중 요청 → 플랫 벤치프레스 |
| 00:33.3 | 머신 체스트 프레스 → 맨몸 스쿼트 |

## 구현

두 운동의 시작 메시에서 리그의 관절별로 가중치를 많이 가진 정점들을 모아 위치와 회전을 추정한다. 골반을 기준으로 연결된 관절의 상대 회전을 쿼터니언으로 보간하고, 각 관절에 원본 표면의 차이를 되돌려 얹는다. 양쪽 끝에서는 실제 저장된 메시를 사용한다. 앉거나 누운 운동은 손을 놓는 자세, 일어선 자세, 벤치에 앉은 자세를 거쳐간다. 발을 디딜 수 있는 구간은 무릎과 발목을 같이 풀고 양발을 시차를 두고 옮긴다. 반복 범위를 따로 지정한 운동은 시작 프레임에 닿은 뒤 원래 반복 진입점으로 짧게 이어준다.

현재 기구의 접촉부는 몸이 빠져나올 때까지 유지하고 다음 기구의 지지부는 올라타기 전에 배치하도록 순서를 잡았다. 공용 부품은 기존 메시의 동일성으로 짝을 찾고, 일부 타워와 웨이트 스택은 크기와 위치로 대응시킨다. 같은 덤벨 부품은 손목을 따라가고, 데드리프트에서 재사용한 바벨 샤프트는 몸 앞쪽에 비켜 있다가 벤치 위에서 손으로 돌아온다. 한쪽에만 있는 기구는 내려가며 사라지거나 올라오며 나타난다.

카메라는 사용자가 보던 방향과 거리에서 시작해 다음 운동의 기본 구도로 이동한다. 전환 중에는 궤도 조작과 확대를 잠근다. 가까운 구도에서는 먼저 물러나고, 중간에 캐릭터가 화면 밖으로 나가거나 카메라가 기구에 가까워지는 구간은 거리를 보정한다.

## 확인 결과

- 실제 데스크톱 뷰어에서 7개 장면을 30fps로 촬영했다. 각 장면의 도착 운동을 수정 전 뷰어에서 따로 열어 여러 시점의 반복 진행도, 인체 정점, 워치 위치와 기구 행렬을 비교했다. 비교한 값이 모두 일치했고 기본 카메라도 같은 위치와 방향으로 돌아왔다.
- 덤벨 컬 1.20초 부근에서 전환을 요청한 뒤 이전 뷰어와 같은 자세로 2.60초까지 진행했다. 2.60초에 전환이 시작됐고 4.60초에 다음 반복이 시작됐다. 대기 중 목적지 변경, 확대 상태에서의 후퇴, 전환 중 조작 잠금과 도착 후 복귀도 브라우저에서 확인했다. 전환 중 60kg을 선택한 경우에도 같은 중량을 적용한 기존 뷰어와 도착 운동의 기구 행렬이 일치했다.
- 클린의 한 방향 반복, 좌우 교대 컬, 시작 구간을 생략하는 아놀드 프레스를 추가로 확인했다. 덤벨 컬 → 덤벨 레터럴 레이즈는 덤벨 부품 10개, 플랫 → 인클라인 벤치는 부품 37개를 매칭했다. 영상의 랫 풀다운 → 케이블 컬에서는 타워·스택 등 12개를 이어서 움직였다.
- 현재 목록 251개가 가리키는 고유 모션 248개의 시작 메시를 읽고, 서로 다른 모션의 방향 있는 조합 61,256개에서 경로와 중간 자세를 계산했다. 이 검사는 전 조합의 자세를 계산할 수 있는지 확인한다. 화면상 접촉은 녹화한 사례에서 검토했다. 관련 기존 테스트 26개도 통과했다.

## 육안 검토와 남은 점

네이티브 `gpt-6.2-astra`가 시간 순서대로 뽑은 프레임을 검토했다. 첫 검토에서 허공에 앉는 모습, 벤치 바가 남아 있는 상태로 상체가 일어나는 장면과 중간 구도에서 머리가 잘리는 구간을 짚었다. 지지부가 준비된 뒤 앉도록 순서를 바꾸고, 손을 놓은 바의 이동과 카메라 보정을 따로 조정해 다시 촬영했다. 이어진 검토에서 랫 풀다운 손잡이가 1.17초에 얼굴을 가려, 앉기 전까지 손잡이를 위로 들어 올렸다. 최종 비교에서 이 겹침이 해소됐고, 체스트 프레스에서 양발이 가로대를 빠져나온 뒤 기구가 사라지는 순서도 확인했다.

공유 바벨이 벤치 위에 공중으로 이동하는 부분에는 게임 연출 느낌이 남는다. 랫 풀다운은 1.87초에 오른손이 손잡이 끝보다 약간 바깥에 있다가 1.97초에 그립을 감싼다. 체스트 프레스에서 빠져나오는 뒤발과 가로대는 1.07~1.10초에 정면상 윤곽이 잠깐 겹치며 깊이 방향의 관통은 확인되지 않았다. 일부 발걸음은 아직 무게감이 가볍다. 기구별 지지 위치와 가동 범위를 충돌 물리로 푸는 방식은 아직 들어가지 않아, 낯선 기구 조합과 자유 카메라의 모든 각도에 대해서는 관통이 없다고 보장할 수 없다. 실제 폰에서의 프레임 시간과 앱 스와이프는 이번 범위 밖이다.

## 데스크톱 확인과 앱 연결

생성된 뷰어 묶음을 로컬 HTTP로 열고 주소에 `?ex=flat_bench&next=lat_pull_down`을 붙이면 시작 자세에서 전환을 볼 수 있다. 이미 운동이 재생 중인 화면에서는 브라우저 콘솔의 `window.transitionTo('lat_pull_down')`으로 현재 반복이 끝난 뒤 바뀌는 동작을 확인할 수 있다.

모든 조합의 전환을 저장할 필요 없이 클립마다 시작 자세와 접촉 정보를 두면 목록 전체에서 재사용할 수 있다. 앱에서는 스와이프가 확정되거나 마지막 세트 뒤 다음 운동이 정해질 때 같은 WebView에 목적 운동 ID를 넘긴다. 인접 운동의 첫 자세, 기구와 기본 구도를 미리 읽으면 반복 경계에서 로딩 대기를 줄일 수 있다. 그전에는 기구 제작 단계에서 공용 부품 ID, 그립과 지지면, 하차 방향을 메타데이터로 남기고 대표 기구군마다 양방향 접촉을 검증하는 편이 좋다. 앱의 페이저 연결과 배포는 하지 않았다.
